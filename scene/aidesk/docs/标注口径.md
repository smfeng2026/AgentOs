# 6H-CrossApp-Intent 标注口径与审核指南

> 版本 v1.0 · 2026-11-28 · 来源：48 条试点样本人工陪审（47 原始批准 + 1 重建，1 拒绝）提炼。
> 适用：annotator / reviewer / adjudicator 提示词修订、人工审核、放量生成质检。
> 配套：[数据集设计.md](数据集设计.md)、[场景架构分析.md](场景架构分析.md)、[app_bundle_map.json](app_bundle_map.json)（系统侧包名参考，训练集仍用角色名）。

## 0. 总原则

1. **标签跟真实事件语义，不跟配比**：15 相关 / 15 无关是目标不是硬约束（硬边界 10–20 无关）；不为凑数虚标 supporting。
2. **关系标签相对意图框架**：先确定意图是「当前计划 / 调整 / 被取消的计划」，再定 supporting/contradicting；同一事件在不同框架下关系可不同。
3. **克制优先**：证据不足时 purpose=unknown、status=emerging、confidence=low、supporting 可空；宁可少断言，不过度推断。
4. **App 名不暴露标签**：训练集用封闭通用角色名（im_app 等），同一 App 承担多角色；真实 bundleName 仅用于系统/部署侧。

## 口径 A：supporting 边界

**判 S（决定性证据）**：
- 下单 create_order、支付 pay、预订 book、报名 submit_registration；
- 对方确认（客户确认邮件、朋友明确应约、同事确认）；
- 日历创建 create_event；
- **本人明确敲定消息**（「那就定周六 18:00…」「车我订好了，8 点出发」）；
- 外部确认通知（银行消费提醒、发货通知、预约成功通知）；
- **核心承诺事件本身的提醒**（会前提醒、体检空腹提醒）。

**判 i（相关兴趣 / 弱证据）**：
- 搜索 search、浏览 browse、查看 view_detail/view_order/view_schedule、比较 compare、收藏 collect；
- 发起邀约 / 征询（「周六有空吗？」「请确认时间地点」）；
- 协同沟通（分工、材料审阅、行程商量）；
- **辅助后勤提醒**（出发提醒、路程提醒）；
- **模糊邀约**（「改天吃饭」「到时候约」「回头再定时间」）——无具体承诺，S 可空。

**关键细分**：
| 情形 | 判定 | 例 |
|---|---|---|
| view_order 即使内容显示「已支付/已出库」 | i（看动作类型，不看内容状态） | c03-s01-9c49fd63 e029 |
| 本人敲定消息 vs 发起邀约 | 敲定=S，邀约=i | c04-s01-9e1006a1 e007=S / e001=i |
| 核心事件提醒 vs 出发后勤提醒 | 核心=S，后勤=i | c05-s01-c7e744c0 e029=S / c02-s01-68d56630 e025=i |
| 外部确认通知（银行/发货/预约成功） | S | c03-s01-b2ab5b74 e024 |

## 口径 B：歧义噪声

疑似相关但**缺地点 / 实体关联**的事件 → 保持 **unrelated**，把歧义写入 `unknown_information`，不凭怀疑标 i。
- 例：c01-s04-7f2e82ab e015「搜索附近打印店」无城市 → unrelated + unknown 记录「是否需打印合同」。
- 反例（不要做）：因「打印店可能印合同」就标 i。

## 口径 C：品类弱关联

- **同品类**弱关联 = i（同品类 + 同区域 + 时间邻近）；
- **仅区域相同、异品类**浏览 = unrelated。
- 例：c04-s01-9e1006a1 e023 烤肉外卖浏览（同品类烤肉）=i；e021 火锅榜（异品类）=unrelated。
- 原则：品类一致比区域一致更能说明语义关联，避免关键词共现捷径。

## 口径 D：弱证据克制与粒度

1. **纯浏览/搜索/收藏样本**：supporting 可空、status=emerging、confidence=low；purpose=unknown 或「兴趣主题」（hobby/renovation/banking 等），但必须配 emerging/low + unknown 项，**不得断言具体计划**。
   - 例：c05-s05-2a633e7a 颈肩健康关注（S 空 / unknown / emerging / low）。
2. **噪声不升格意图**：日常缴费、查余额、购物车等单条噪声不得组成意图；**难负例（hn_*）尤其禁止**。
   - 反例：c05-s05-89eb7071 盲标把电费/购物车升格为意图 → 删除；c12-m05-df2dd78e i003「考虑去郑州」由 hn_flight/train_other_city 两条难负例升格 → **删除 i003，还原 unrelated**。
3. **粒度合并**：同域弱内容兴趣合并为一个「内容关注」意图，不按主题拆；**只有出现独立承诺证据簇才拆独立意图**。
   - 例：c05-s05-89eb7071 睡眠+颈椎合并；c08-s03-86cfa2cb 生日蛋糕浏览并入家宴意图（未下单、无独立簇）。
4. **多意图分离**：C12 需真正独立证据簇；共享事件可双挂多个 intent_ids，但不得因同窗口就合并。
   - 例：c12-m01-21852408 e015 同时提及出差+换机 → 双挂 i001/i002（合法交叉，非泄漏）。

## 口径 E：status 语义

| status | 含义 | 判据 |
|---|---|---|
| emerging | 仅兴趣 | 只有浏览/搜索/收藏 |
| considering | 权衡无承诺 | 有意向但无强承诺（含模糊邀约） |
| planned | 有安排无强承诺 | 有日程/搜索但无支付/确认 |
| **confirmed** | **有强承诺** | **支付/预订/对方确认（不论行程是否未来）** |
| completed | 实际发生 | 签收/使用/到场 |
| cancelled | 已取消 | 取消+退款 |

**易错点**：
- 未来行程只要有机票/酒店/订座支付 + 确认 → **confirmed**，不是 planned（样本 1–6）。
- 手机已支付但**未签收** → confirmed，**不是 completed**（c12-m01 ×2）。
- 预约成功通知「已确认」→ confirmed（c09-s01 ×2）。
- 已下单支付后取消退款 → **cancelled**，不是 considering（c03-s06-95f38eb6）。

## 口径 F：D6 状态变化框架

**统一以「当前计划 / 调整 / 被取消的计划」为意图框架，不用「原计划」框架。**

- **取消 / 退款 / 标记取消事件 = S**（状态变化的决定性证据）。
- **原计划证据**（原订单/购票/碰头约定）：
  - cancelled 型 → i（历史）；
  - 调整型 → C（反证，c11-s06-4476d3fc）或 i（历史，重建条 c11-s06-0f813ab3）——两者皆可，同批尽量统一，差异记录在案。
- **真实冲突证据 = C**：如官方取消公告 vs 群传「照常举行」（c07-s06-c9dd2602 e015 保留 C）。
- **反例（错误框架）**：把意图定为「原观演/原出行」，取消退款标 C、原购票标 S —— c11-s06-9b9b5104 因此被 **reject 重建**。

| 样本 | 框架 | 取消/退款 | 原计划 | 冲突 |
|---|---|---|---|---|
| c11-s06-4476d3fc | 方式调整 | S | C | — |
| c11-s06-0f813ab3（重建） | 方式调整 | S | i | — |
| c01-s06 ×2 / c07-s06-22cb643d | 被取消计划 | S | i | — |
| c07-s06-c9dd2602 | 被取消计划 | S | i | e015=C |

## 审核流程与修正约定

### 流程
1. `python -m src.cli review --sample-id <id>`（或 `review --export`）→ 一屏含事件表（Gold vs 盲标 ⚠️）+ 意图/事实 + 审查员 issues + 裁决理由 + 5 项清单。
2. 按口径 A–F 核**最终 gold**（审查员 issues 多为裁决前状态，须看裁决后结果，不只看 passed/flag）。
3. 判定：`approve --by <名> --note`；结构性错误 `reject --note` 后 `generate --template-id <模板>` 重建重审。
4. `build`（approved-only）→ `evaluate --self-check --gold data/splits_pilot/test.jsonl data/splits_pilot/challenge_test.jsonl`。

### 修正约定（手改 gold 时）
- 关系迁移：同步更新意图 `supporting/related_interest/contradicting_event_ids` **与** `event_labels`（镜像一致）。
- **confirmed_facts 仅引 S**：事件从 S 降 i 时，引用它的 confirmed_fact 迁到 inferred_facts。
- 改 status/confidence 按口径 E；删意图须同步 `unrelated_event_ids` 与 `global_observations.intent_count`。
- 改后必跑镜像 + facts 引用校验；修正内容写入 approve note 留痕。
- **泄漏字段**：删除非自然目的字段（如 weather 的 `query_purpose`，c08-s03-2b914f19 e029）；自然字段（payment `purpose`、`cancel_reason`、`refund_reason`）保留。model_inputs 与 internal_labels 同步改。

## 流程级改进项（放量前处理）

1. **裁决器口径漂移**：D6 框架、status、弱证据升 S 反复出现 → 把口径 A–F 写进 annotator/adjudicator 提示词。
2. **confirmed/inferred 约定**：「confirmed_facts 仅引 S」把直接观察事实挤进 inferred，认识论不准 → 放宽为「confirmed 可引任何相关事件」或明文约定。
3. **generator_event_id 命名空间伪引用**：related 与 noise 共用 e### 重号，污染溯源审计 → 独立命名空间。
4. **噪声池**：同 App 异主题强干扰应标 hard_negative（天文科普/材料科学）；固定文案自然度（周日出现「工作日午餐」）。
5. **生成真实性**：行程时间线可行性校验（c12-m01-21852408 e024 15:30 晚于 14:00 会议）；模糊邀约不进 S；人数算术自洽。
6. **judge 校准**：flash 级 judge 对细微证据分级能力有限，人工抽检校准 judge–人一致性，必要时裁决器升级。
