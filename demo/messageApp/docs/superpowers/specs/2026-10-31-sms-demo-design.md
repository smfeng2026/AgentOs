# 短信 Demo 设计

## 目标与外观
使用 HarmonyOS ArkUI 实现本地短信 Demo。以 IMG_7554.PNG 和 IMG_7555.PNG 为外观参考：白色背景、大标题“信息”、蓝紫色联系人头像、分隔线列表、底部搜索和新建按钮；详情为左侧灰色接收气泡、右侧绿色发送气泡，顶部联系人与返回按钮，底部回复框。不模拟系统状态栏，由设备显示。

## 页面与交互
- 列表 `pages/Index`、短信详情 `pages/MessageDetail`、编辑页 `pages/MessageEditor` 分别为独立 `@Entry`，统一注册在 `main_pages.json`。点击会话通过 `router.pushUrl` 传递 `threadId`，每次创建详情页路由实例。
- 新增、编辑使用 `router.pushUrl`；新增保存通过 `replaceUrl` 进入详情，编辑保存、取消及详情返回通过 `router.back` 返回，保持正常路由栈。
- 各页提供框架生命周期 `onPageShow/onPageHide`，用 `SmsDemo` 标签记录页面路径。列表和详情在 `onPageShow` 重新加载共享持久化数据。移除状态模拟切页和自定义 `onPageChange`；系统侧页面变化由实际路由驱动。
- 列表显示联系人或号码、最新内容摘要、日期和未读标记；支持按联系人和正文搜索。
- 点击会话进入详情并标记已读；回复框支持发送本地消息。
- 新建表单可填写联系人/号码、短信正文、接收/发送方向和时间；保存后显示在列表中。
- 详情支持编辑联系人，编辑或删除单条消息；列表编辑模式支持多选删除会话。删除需要确认。
- 空列表、无搜索结果、空正文等情况提供明确提示。

## 数据
7 个预置会话完整保留用户提供的主题与正文，作为接收短信显示；链接仅作为短信文本展示。首次启动初始化数据，后续新增、修改、删除和已读状态使用本地 preferences 持久化，重启不覆盖。仅本机演示，不申请短信权限，不发送真实短信。

## 图标与结构
message_icon.png 用于应用图标、Ability 图标和启动图标。数据模型、种子数据与存储逻辑独立于页面。界面按参考图做尺寸自适应。

## 验证
检查 ArkTS 编译；验证初始 7 条内容、搜索、进入详情、收发方向、新增、编辑、单条与批量删除以及持久化。若无可用构建工具或模拟器，明确报告验证限制。

2026-10-31 路由调整：`assembleHap` 构建成功，并检查 HAP 内页面配置包含三个路由。设备侧应验证列表 → 详情 → 编辑 → 返回详情 → 返回列表；同时核对 `SmsDemo` 生命周期日志与 AMS 侧监听。应用日志只用于辅助核对，不等同于已验证 AMS 回调。

## 方案选择
推荐原生 ArkUI 与本地 preferences：适合当前空白 HarmonyOS 项目，交互完整且可离线演示。替代方案是仅做内存原型（重启丢失修改），或接入真实短信/后端（涉及权限与服务，超出本次本地 Demo 范围）。
